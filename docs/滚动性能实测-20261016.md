# Android SSH 终端滚动实测（2026-10-16）

本次测试关注中文密集的真实 SSH + tmux TUI 在大网格下的滚动表现。
bakaSSH 使用已发布的 0.1.2，未修改生产渲染或 SSH 代码。

## 相同网格对照

实际终端 / SSH PTY 均为 **154 列 × 134 行**，每个应用三轮。
“整段”包含手势间暂停；“移动期间”仅取手指正在移动的子区间。
合计 FPS 使用总帧数除以总时长，不取三轮 FPS 的算术平均。

| 应用 | 各轮 FPS | 整段帧数 / 秒 | 整段 FPS | 移动期间帧数 / 秒 | 移动期间 FPS |
|---|---|---:|---:|---:|---:|
| bakaSSH 0.1.2 | 30.01 / 31.23 / 29.80 | 217 / 7.150 | **30.35** | 186 / 5.793 | **32.11** |
| 官方 Termux 0.118.3 | 18.73 / 15.76 / 16.87 | 119 / 6.956 | **17.11** | 98 / 5.601 | **17.50** |
| 本地改动版 Termux 0.118.0+tmuxfix3instr | 2.99 / 1.80 / 1.70 | 18 / 8.576 | **2.10** | 16 / 7.221 | **2.22** |

bakaSSH 与官方 Termux 的整段 FPS 比值约 **1.77**。本地改动版与官方版本的基础版本也不同，
不能据此把全部性能差异归因于改动版补丁。

## 帧间波动

| 应用 | 三轮呈现间隔 P50（ms） | 三轮呈现间隔 P95（ms） | 手势阶段 jank |
|---|---|---|---:|
| bakaSSH | 14.19 / 14.16 / 13.43 | 35.85 / 33.88 / 40.99 | 96.31% |
| 官方 Termux | 34.92 / 35.64 / 32.23 | 55.47 / 46.82 / 47.74 | 100% |
| 本地改动版 Termux | 191.41 / 260.58 / 270.86 | 291.17 / 1220.71 / 410.50 | 100% |

jank 使用 FrameTimeline 的标记，包含 App Deadline Missed、Buffer Stuffing 等类型，
并非单一的应用绘制超时指标。三个应用对应阶段的 dropped_frames 均为 0；
没有生成新帧的停滞不会自动计入该值，不能因此声称零卡顿。
呈现间隔中位数也不能倒推出整段 FPS，整段还包括暂停和长时间没有新帧的区间。

## 不同网格下的压力与兼容性观察

- **bakaSSH，335×307：**三轮整体 13.76 FPS、移动期间 13.87 FPS。
  额外六组共 18 次滑动，手势阶段 223 帧 / 14.272 秒，整体 15.63 FPS、移动期间 15.23 FPS；
  整个过程含准备与检查约 44.2 秒，未观察到 ANR 或终端退出。这只是本次短时结果。
- **JuiceSSH 3.2.2，字号界面值 2、PTY 209×193：**第一组 34.00 FPS，第二组 17.21 FPS，
  第三至第五组继续注入滑动，但未见应用继续呈现新帧。第六组出现输入分发超时 ANR，
  距首次手势约 41 秒。系统记录 TerminalEmulatorActivity 等待 MOVE 事件超时 5000 ms，
  随后旧进程终止并启动 MainActivity，界面表现为终端退回首页。第一组初期网格仍在收敛，
  不能视为稳定性能排名；具体阻塞调用和根因尚未定位，不能判定为 OOM。
- **ConnectBot 1.11.0：**本次 tmux 场景无法正常滚动，停止测试。
  包括 50×50 在内的探索没有形成有效的同条件结果，不记为 0 FPS，不参与性能排名。

以上网格不同，不能与 154×134 表格直接比较。

## 方法

- 设备：OPPO PLB110，Android 16，屏幕 1256×2760、density 560；动态刷新率。
- 场景：真实 SSH 会话中的 tmux TUI，关闭输入法。
- 手势：手机端脚本注入，x=628，y=400 与 1200 往返；每次移动 800 px、60 个 MOVE，
  目标间隔 8 ms，手势间暂停 150 ms。各阶段实际时长按 trace 计。
- 计数：Perfetto FrameTimeline，筛选目标应用的有效 surface frame，
  以 `actual_frame_timeline_slice.ts + dur` 作为呈现时点，按手势阶段及移动子阶段统计。
- 网格：检查实际 View/native 网格与 SSH PTY，主动刷新 tmux 客户端，
  不仅凭 tmux 内部尺寸判断。154×134 终端内 tmux 内容区为 154×133，另有一行状态栏。
- bakaSSH 匹配网格：测试 instrumentation 将终端 View 高度限制为 2033 px，宽度 1186 px，
  单元格约 7.70×15.17 px、字号 13.1 px，使实际可见/native/PTY 网格均为 154×134。
  高度限制只在测试中使用；运行的是发布版的 Activity、渲染器和 SSH 实现。

## 结论边界与下一步

真实 TUI 内容随时间变化，各应用的字体度量、实际显示面积和滚动行为也有差异。
本次没有锁定相同字节流与相同画面序列，属于现场对照，不是完全控制变量的渲染器微基准。
同网格结果说明 bakaSSH 在本次场景中有帧率优势，同时明显的 jank 表明它仍需优化。

bakaSSH 极密网格的部分内部日志区间中，draw 均值约 58.6 ms，其中栅格化约 57.8 ms，
提示后续优先定位文字与行缓存重绘成本。这是诊断线索，不是系统 FPS，也没有完成优化归因。
接下来补固定内容回放、连续缩放后滚动及更长时间的稳定性测试，路线见[后续计划](后续计划.md)。
