# 方块元素拼缝 · 0.4.7

2026-11-19。用户在 0.4.6 真机截图里指出：Claude Code 启动页的像素 logo（`▐▛███▜▌` 等方块字符）有明显的 1px 竖缝。
versionCode 17，沿用既有包名和签名。

## 原因（两处叠加）

1. **字形墨迹恰好等于小数步进。** 方块元素用字体绘制时，墨迹宽度等于字体步进（59 列时约 20.1px），
   格子落点各自取整；相邻两格起点相差 21px 处，前一格最右一列只有约 10% 覆盖。
   0.4.2 的字形留白只对本来就画出格子的制表符有效，对恰好铺满的方块无效。
2. **背景与前景逐格交替绘制。** 行位图按「背景、前景」逐格画，下一格的背景矩形盖住上一格前景的最后一列；
   背景使用小数边界，且 Android 10+ 的 `new Paint()` 默认开抗锯齿，于是每个格子边界都有一列半覆盖像素，
   在空白背景上也能测到（亮度 14 对 16），在方块上就是暗缝。

修完第 1 处后，CI 截图逐像素核对仍有缝，由此定位到第 2 处。

## 修复

- U+2580–259F 共 32 个方块元素不再用字体，按八分之一格的矩形绘制；所有边界经同一取整函数
  `BlockElements.edge` 从列号 / 行号算出，相邻格子、相邻行共享同一条整数边界。阴影 `░▒▓` 用 25% / 50% / 75% 实心填充。
- 行位图改为两遍：先刷整行背景（同色连续格合并），再画全部前景；背景段同样使用整数边界、铺满行位图高度。
- 背景与方块的 Paint 显式关闭抗锯齿；捏合实时绘制与光标走同一套规则。

## 验证

- 主机回归 `BlockElementsRegression`：复现旧画法的低覆盖列；6 种视口宽 × 127 种列数下整行全块逐像素恰好覆盖一次；
  左右半块拼合、双宽边界、相邻行边界一致；32 个字符面积与 Unicode 定义一致。
- 设备回归（`RenderingRegression`）：37 列小数格宽、部分格子带不同背景色的整行 `█`，三条扫描线逐像素严格等于前景色。
  原制表线检查只要求「不是背景色」，半覆盖像素也能通过，这是缝此前没被发现的原因。
- CI 模拟器 60 列截图：仿 Claude logo 区域半覆盖像素为 0。
