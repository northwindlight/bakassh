# SSH 转发与后台权限 · 0.4.8

入口：主页「端口转发」，或主机菜单 →「端口转发」。先保存 SSH 主机及其密钥或密码。

## 界面

- **状态卡**：未开启 / 正在连接 / 转发中 / 连接断开（自动重连中）/ 启动失败，失败时直接显示原因。主页入口同步显示状态。
- **经由服务器**：点按切换已保存主机。命令模式下主机由命令里的 user@host 决定。
- **规则**：每条规则一张卡片，左侧 L / R 标出本地或远程，主行是「监听 → 目标」（监听地址为回环时只显示端口），副行说明在哪一侧监听、谁能连。点卡片编辑，⋮ 菜单上移、下移、删除；删除可撤销。
- **表单 / 命令**：规则标题右侧切换。表单下方显示等价的多行 ssh 命令，可复制；命令模式直接编辑同一条命令，切回表单保留规则顺序，出错时保留原文并标出原因。
- **底部按钮**：未开启时为「启动」；运行中为「停止」，有未应用的改动时再出现「应用修改」。
- 未启动的改动自动保存为草稿，离开页面不会丢。

## 用法

例如将手机 2222 端口通过 SSH 服务器转到服务器自身的 22 端口：

```sh
ssh -N -L 0.0.0.0:2222:127.0.0.1:22 alice@server.example
```

监听 127.0.0.1 只供手机本机连接；0.0.0.0 允许局域网设备连接。低端口（如 22）是否可用取决于手机系统；绑定失败会显示错误，可换 2222。
-L 的目标从 SSH 服务器访问，-R 的目标从手机访问。远程监听地址还受服务器 GatewayPorts 限制；服务器需允许相应的 AllowTcpForwarding / PermitOpen。

支持多个 -L / -R、IPv6 方括号、-p、-l、-g、-N、-T、-n，以及 ExitOnForwardFailure=yes、ServerAliveInterval、ServerAliveCountMax。
当前不支持 -D、-i、ProxyCommand 或远程 shell 命令。命令由应用解析为 JSch SSH 通道，不启动本地 shell；认证方式来自匹配的已保存主机。
首次连接需要确认服务器指纹，指纹变化会阻止连接。不会关闭主机身份校验。

## 后台与恢复

SSH 转发由独立前台服务持有，包含常驻通知、停止按钮、CPU 休眠锁和 SSH 保活；无需持续打开配置页，也不依赖 ADB。
网络断开后每 3–30 秒重试，认证错误、主机指纹变化、转发规则被拒绝等需要手动处理。
打开「开机后自动恢复」后，收到系统开机或应用更新通知会尝试恢复。停止转发后不会再自动启动。
临时密码和私钥口令不落盘，进程重建后需要重新输入；已保存密码继续使用原有 Android Keystore 保护。
系统强行停止应用、自启动限制或虚拟机未启动时，无法保证自动恢复。此功能不负责启动 Linux 虚拟机。

「后台常驻」始终提供系统设置入口，已免电池优化也不等于厂商允许后台。
ColorOS 的应用耗电管理需由用户选择「完全允许后台行为」；前台服务和休眠锁不能绕过 Hans 冻结。
应用使用公开系统入口，不能直接替用户修改厂商开关。

## 验证

- 主机回归覆盖命令解析、IPv6、规则与多行命令往返、空规则草稿、非法参数，以及真实 SSH -L / -R 的双向二进制传输、端口释放和部分失败清理。
- CI 模拟器截图流程在转发页添加 -L / -R 规则并启动，分别从手机和 CI 宿主机连入，确认收到 sshd 横幅。
- OPPO PLB110 / Android 17：真实 SSH -L 转发到远端服务器与本机 Linux 虚拟机；手机 22 端口绑定成功，并从同一 Wi-Fi 的电脑登录。
- ColorOS「完全允许后台行为」开启后，SSH 会话后台与锁屏复测通过；关闭时曾在约 10 秒后被 Hans 冻结并销毁套接字。
- 应用覆盖更新后恢复已开启转发已实测。整机重启后的恢复尚未实测，厂商后台策略仍需逐机确认。

运行 SSH 测试需 JDK、C 编译器、ssh-keygen、Python 3 / Paramiko，以及构建依赖中的 JSch：

```sh
export JSCH_JAR=/path/to/jsch-0.2.26.jar
bash tests/host/transport.sh
bash tests/host/forwarding.sh
```
