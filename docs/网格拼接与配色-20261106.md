# 网格拼接、常驻后台与终端配色

2026-11-06，版本 0.4.2 / versionCode 12（GitHub Release 与 `~/sshterm/releases/v0.4.2/`）。

## 常驻后台改为默认

- 只要有活动会话，`SessionService` 就以低优先级前台服务运行，并**自动**持有
  `PARTIAL_WAKE_LOCK` 与 `WIFI_MODE_FULL_HIGH_PERF` 两个休眠锁。
- 手动开关全部删除：通知里的「保持唤醒 / 释放休眠锁」按钮、设置里的常驻开关都不再存在。
- 通知只保留「断开全部」；「后台常驻」页只留系统级入口（电池优化、通知、应用信息）。
- 设置项与终端菜单统一更名为「后台常驻」。
- 电池优化豁免要用户在系统里点「允许」，这一条无法自动化；
  「后台常驻」页里保留了入口，厂商的额外后台限制同理。

## 默认快捷键

默认两行改成：

| 第一行 | | | | |
| --- | --- | --- | --- | --- |
| Esc | Tab | Alt | ↑ | 键盘 |
| Ctrl | Shift | ← | ↓ | → |

- 新增 Shift 与「键盘」（直接唤出输入法）；Ctrl 从第一行挪到第二行；Home / End 不再默认出现。
- 三个历史默认方案（含 0.4.1 的 `ESC,TAB,CTRL,ALT,UP|HOME,END,…`）在未自定义时自动迁到新默认；
  用户自己保存过的布局保持不动。回归见 `KeyLayoutRegression`。

## 选择跨屏滚动

旧实现把选区冻结在一屏快照上：手指拖到边缘时屏幕不动，超出一屏的文字选不到、也复制不了。

现在：
- 选区改用**绝对行号**（0 = 屏幕首行，-1 = 屏幕上方一行）保存快照，滚出来的行按绝对行号补进选区，
  所以选区可以跨过一屏，复制时按行拼接。
- 拖选时手指进入上下边缘带（1.5 行高）自动滚动，40ms 一行，到头自动停；
  焦点跟着刚露出的那一行走，快照同步重画。
- 自动滚动走新增的 `NativeTerm.scrollView()`：只改本地 `view_offset`，
  绝不转发成远端滚轮或方向键——鼠标模式下的 tmux / Claude Code 不会被喂事件。
- 备用屏（alt screen）没有本地历史，沿用原行为。
- 回归：`SelectionRegression` 覆盖「跨回滚选区的文本」「两端夹紧」「鼠标模式下不产生远端输出」。

## 网格拼接缝隙

现象：等宽格子的制表线（`─` `│` `┼`）、块元素（`█` `▀`）和彩色背景块在拼接处出现
1px 细缝，整条线看起来像虚线。

根因有两条，彼此独立：

1. **位图宽度与落点的取整方向不一致。** 单元格宽是连续值（视口宽 / 列数），
   字形位图宽度按 `round(cellW)` 取整、落点又各自按像素取整。1080px / 150 列时
   `cellW = 7.2`、位图宽 7，而落点序列 `0,7,14,22,29,…` 每 5 格就多跳 1px，
   整行 30 处空列。
2. **位图被裁在单元格边界上。** Cascadia Mono 的制表符是**故意画出格子**的：
   `─` 左右各溢出 0.05em，`│` / `┼` 上下各溢出 0.2em，用这段重叠和邻格接成一条不断的线。
   位图裁在格子边上会切掉这段重叠带。

修复：`glyphFor` 生成的位图四周各留 `glyphPad = max(2px, ceil(0.06em))` 像素，
绘制时整体外移 `glyphPad`，内容仍对齐格子原点；位图尺寸与落点统一由
`GlyphGeometry` 计算，主机侧回归直接调用同一份代码。

验证：
- `tests/host/GlyphGeometryRegression`：20–400 列 × 5 种视口宽共 1905 种布局，
  断言相邻位图重叠 > 1px；同一回归先用旧算法算出 150 列下确实有 30 处缝，
  证明这条检查能抓住修复前的问题。
- `RenderingRegression`（androidTest）新增像素检查：整行 `─` 在任一列都不允许露出背景色。
  本轮无 ADB 设备，只编译未运行。

## 终端配色

原 ANSI 16 色用 libvterm 内置表，蓝 `#0000E0`、紫 `#E000E0` 在近黑背景 `#101014` 上
WCAG 对比度只有 1.88 / 4.74，蓝色基本看不清。

Windows Terminal 的配色不是算出来的，而是一张张固定方案表（Campbell、One Half Dark…）。
对照结果（同一 `#101014` 背景）：

| 方案 | 蓝 | 对比度 | 紫 | 对比度 |
| --- | --- | ---: | --- | ---: |
| libvterm 原表 | `#0000E0` | 1.88 | `#E000E0` | 4.74 |
| WT 默认 Campbell | `#0037DA` | 2.31 | `#881798` | 2.37 |
| **WT One Half Dark** | **`#61AFEF`** | **8.03** | **`#C678DD`** | **6.45** |

Campbell 是为 Windows 控制台自己的深色背景调的，紫色放到更黑的底上反而比原表更难认，
因此采用 WT 内置的 One Half Dark：

| 索引 | 名称 | 值 | | 索引 | 名称 | 值 |
| ---: | --- | --- | --- | ---: | --- | --- |
| 0 | black | `#282C34` | | 8 | bright black | `#5A6374` |
| 1 | red | `#E06C75` | | 9 | bright red | `#E06C75` |
| 2 | green | `#98C379` | | 10 | bright green | `#98C379` |
| 3 | yellow | `#E5C07B` | | 11 | bright yellow | `#E5C07B` |
| 4 | blue | `#61AFEF` | | 12 | bright blue | `#61AFEF` |
| 5 | purple | `#C678DD` | | 13 | bright purple | `#C678DD` |
| 6 | cyan | `#56B6C2` | | 14 | bright cyan | `#56B6C2` |
| 7 | white | `#DCDFE4` | | 15 | bright white | `#DCDFE4` |

其余 14 色在 `#101014` 上的对比度都在 3.1 以上（只有 ANSI 黑贴近背景，属预期）。
16–255 的 256 色立方仍按标准 xterm 映射，不随方案改。

调色板在 `libvterm_jni.c` 里通过 `vterm_state_set_palette_color()` 覆盖，
vendored libvterm 源码保持原样。验证：`NativeRegression` 新增
「ANSI palette is One Half Dark」，走 `SGR → libvterm state → color_to_rgb` 全链路比对 16 色。
