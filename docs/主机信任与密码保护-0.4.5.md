# 主机信任与密码保护 · 0.4.5

versionCode 15，沿用既有包名和签名。当前为等待 ADB 验收的候选版，尚未发布 GitHub Release。

## 主机公钥与更新

- 校验发生在 SSH 密钥交换阶段、用户认证之前；JSch 使用 `StrictHostKeyChecking=yes`。
- 首次连接显示地址 / 端口、公钥算法及 SHA-256 指纹，必须明确选择“信任并连接”才能保存并继续认证。
  以前保存的主机没有可信公钥记录，也会首次确认，不从旧连接日志自动建立信任。
- 相同地址与端口的不同账户共用主机信任；不同端口分别保存，域名大小写与 IPv6 外层括号会规范化。
- 公钥变化立即阻止连接，显示新旧指纹；不会弹出一键替换，也不会发送登录凭据。
- 主机卡片菜单“主机公钥 / 指纹”支持查看算法与指纹、复制 OpenSSH 格式公钥、移除记录。
  换钥拦截弹窗也可直接进入管理。核实身份后移除旧记录，再重新连接、确认新指纹，即完成更新。
  记录无法解析时仍可明确移除；移除操作会核对当前记录，避免误删并发更新。
- 同时确认同一地址时，后来的不同公钥不能覆盖已保存记录。保存失败则拒绝连接；
  取消或关闭会话会终止等待，迟到的点击不能重新批准。界面停止 / 切换会话只隐藏弹窗，确认请求由服务保留，
  回到对应会话后继续显示，不在后台默认信任。

## 保存密码与迁移

- 每个保存密码使用 AES-256-GCM，独立随机 96-bit IV、128-bit 认证标签；密钥由 Android Keystore 生成和持有。
  加密上下文绑定主机 ID、地址、端口与用户名，移植到其他主机配置不能直接解密。
- Host 元数据序列化不包含明文密码，偏好只保存带版本的认证密文。密码不再通过 Activity Intent 传递，
  编辑 / 连接密码框不自动写入视图保存状态；私钥口令仍仅用于本次解锁，没有扩大保存范围。
- 加载旧配置时生成稳定 ID，先完成全部加密，再同步提交替换旧 JSON，成功后移除明文 `password` 字段。
  加密或提交失败会报告错误并保留原磁盘配置；提交仅改变内存的情况会在下次加载重试。
- 密钥丢失 / 密文损坏时保留主机元数据和原密文，连接时要求重新输入；读取不会生成替代密钥，
  也不会退回同记录的旧明文。编辑主机可重新输入并替换保存密码，或留空保存以清除。
  无法解析的整份主机配置不会被当成空列表后覆盖。
- Android 11 及更早备份规则、Android 12+ 云备份与设备迁移规则均排除 `sshterm.xml`、
  `host_keys.xml` 和应用私有文件（含私钥）。主机配置、凭据和信任记录不会随系统备份迁移到另一设备；
  其他界面偏好保留系统默认备份行为。应用进程内仍需临时持有密码，不声称能抵御已控制应用进程的攻击者。

实现依据：[Android Keystore](https://developer.android.com/privacy-and-security/keystore)、
[Android 备份规则](https://developer.android.com/identity/data/autobackup)、
[JSch 0.2.26 密钥交换与主机校验](https://github.com/mwiede/jsch/blob/jsch-0.2.26/src/main/java/com/jcraft/jsch/Session.java)。

## 本轮离线验证

- 57 项主机回归，含 4 项新增 JCE AES-GCM 检查。
- 21 项真实 loopback SSH 检查，含 10 项新增信任 / 认证顺序检查；服务端审计确认拒绝前没有认证请求。
- 9 项真实存储代码的主机回归，覆盖迁移、乱码 / 空格密码、密钥丢失 / 替换、密文 / 上下文篡改、
  禁止明文回退、损坏 JSON、加密 / commit 失败、并发公钥插入及显式移除更新。
- Debug / Release / AndroidTest 编译和 lintRelease；最终结果随候选交付包保存。

主机存储测试使用偏好适配器和 JCE 密钥后端，不能证明 Android Keystore、触摸或系统后台路径已通过。
Android `security` 模式使用真实 Keystore 与 SharedPreferences、独立随机 alias 和偏好，现阶段只编译、未执行。

## ADB 验收与发布前顺序

1. 保留原应用数据覆盖升级，验证旧主机 / 密码可迁移。禁止 `pm clear`、卸载或测试真实服务器换钥；
   换钥场景使用隔离的合成 SSH 服务端。
2. 安装匹配版本的 Debug 与测试 APK，执行默认手势 / 画面回归，再执行 `-e mode security`。
   检查随机测试偏好和 alias 已清理，真实凭据未被测试修改。
3. 合成 SSH 场景：首连取消 / 确认、杀进程后已知公钥免确认、同地址不同账户 / 端口、换钥拦截、
   查看 / 复制 / 移除主机公钥、新公钥重新确认；等待确认时旋转 / 切换会话 / 退后台 / 关闭会话。
4. 验收 Claude Code 点击、tmux / 非 tmux 滚动、Tab 与方向键长按、中文输入法、复制选区、会话切换。
5. 验收通知回到会话、锁屏 / 退后台持续连接、EOF 画面与强杀后重连边界，记录设备与持续时间。
6. 按 `benchmarks/README.md` 采集修复后性能基线，报告同步耗时与真实呈现帧率各自的边界。
7. 检查通过后安装同签名 Release APK；核对版本 / 签名 / SHA-256，再发布 GitHub `v0.4.5`，
   上传 APK、源码 ZIP 和 SHA256SUMS。本轮不提前发布或宣称真机测试通过。
